# User-Centric Clustering and Repeat Purchase Prediction Analysis

## Notebook order

1. `01_data_preprocessing.ipynb` — Member A: clean `orders.csv`, construct RFM features and `Repurchase_Label`, split customers into train/validation/test, and export CSVs.
2. `02_clustering.ipynb` — Member B: fit train-only imputer/scaler/PCA/K-Means, select k by train silhouette score, export cluster assignments and centroid distances.
3. `03_baseline_models.ipynb` — Member B: compare Logistic Regression and Random Forest with/without one-hot cluster labels; select using validation F1 and evaluate the selected configuration on test.

## Input data

Put `orders.csv` in the same directory as the first notebook. It must contain:
- `customer_id`
- `order_date`
- `order_id`
- `total_amount_usd`
- optionally `returned` (when present, only `returned == 0` is retained)

`customers.csv` is optional in the current pipeline. It is read for a quick inspection only.

## Run

Install dependencies:

```bash
pip install pandas numpy matplotlib seaborn scikit-learn joblib jupyter
```

Run the notebooks in the order above from the repository root. They create an `output/` directory.

## Important methodological notes

- The observation window ends on 2024-12-31. The prediction window is 2025-01-01 through 2025-12-31.
- RFM features are built from observation-window transactions only; the target label is derived from the prediction window.
- The split is performed at customer level, with stratification when possible.
- Imputation, standardization, PCA, and K-Means are fit only on training data.
- The cluster model is unsupervised and does not use `Repurchase_Label` to fit clusters.
- Baseline configurations are selected on validation F1. The test set is used only for the selected configuration.
- The actual best cluster count and all metrics are generated by running the notebooks; do not hard-code values from an earlier run into the final report.
